0開始前：怎麼編譯和執行

C 沒有 runtime 或直譯器，要先編譯成機器碼才能執行。這跟 Node.js 或 Python 最大的不同。

# 裝好編譯器（只需要一次）
sudo apt install build-essential gdb

# 編譯：-Wall -Wextra 開啟警告；-g 加除錯資訊，之後用 gdb 時需要
gcc -Wall -Wextra -g hello.c -o hello

# 執行
./hello

# 把檔案內容當作輸入（1.5 節以後會一直用到）
./count < some.txt
一開始就養成習慣：把每個警告都當成錯誤處理。C 編譯器會放行很多危險的寫法，警告常常就是 bug。可以加上 -Werror，讓編譯器遇到警告就直接失敗。

互動執行時，輸入結束要按 Ctrl-D，這就是 1.5 節會講到的「EOF」。

1.1Getting Started：第一個程式

重點不是印出文字，而是認識一個 C 程式最小的骨架。

#include <stdio.h>      // 引入標準輸入輸出的宣告（printf 在這裡）

int main(void)         // 程式從 main 開始執行，回傳 int 給作業系統
{
    printf("hi, firmware\n");   // \n 是換行，printf 不會自動換行
    return 0;          // 0 = 成功；非 0 = 失敗（shell 的 $? 看得到）
}
  • #include 是前置處理器指令，編譯前會把標頭檔的內容直接貼進來。它不是 JS 的 import，沒有模組系統。
  • 每個敘述用 ; 結尾，區塊用 { } 包起來。
  • 跳脫字元：\n 換行、\t tab、\\ 反斜線、\" 雙引號。
  • 雙引號 "..." 是字串，單引號 'a' 是單一字元，兩者在 C 裡是完全不同的東西。
韌體連結：UEFI 程式的入口不是 main，而是 UefiMain(ImageHandle, SystemTable)，也沒有 printf，要改用 Print()。不過「入口函式、回傳狀態碼」這個概念完全相同。

1.2Variables and Arithmetic Expressions

書上用換算表來介紹變數、while 迴圈和 printf 的格式化輸出。這裡改用「公里換英里」示範同樣的觀念。

#include <stdio.h>

int main(void)
{
    int km;                    // 變數必須先宣告型別才能用
    float miles;

    km = 0;
    while (km <= 50) {
        miles = km * 0.621371f;
        printf("%3d km = %6.2f mi\n", km, miles);
        km = km + 10;
    }
    return 0;
}

這一節的重點

  • 型別是固定的：int 整數、float／double 浮點數、char 字元。宣告之後就不能換成別的型別。
  • printf 格式：%d 是整數，%f 是浮點數。%3d 表示至少佔 3 格並靠右對齊，%6.2f 表示總寬 6 格、小數 2 位。
⚠ 整數除法陷阱（第一章最重要的坑）
5 / 9 的結果是 0，因為兩個整數相除，小數部分會直接捨去。
要得到小數，至少一邊要是浮點數，例如 5.0 / 9。
JS 裡 5/9 會得到 0.555…，所以這個坑特別容易踩到。
韌體連結：韌體裡幾乎不用浮點數，因為開機早期浮點運算單元可能還沒初始化。實務上都用整數搭配位移來處理，所以整數除法和捨去的行為要非常熟。

1.3–1.4for 敘述與符號常數

用 for 改寫上面的迴圈，再用 #define 把寫死的數字換成有名字的常數。

#include <stdio.h>

#define KM_START   0
#define KM_END     50
#define KM_STEP    10
#define KM_TO_MILE 0.621371f

int main(void)
{
    for (int km = KM_START; km <= KM_END; km += KM_STEP)
        printf("%3d km = %6.2f mi\n", km, km * KM_TO_MILE);
    return 0;
}
  • for (初始; 條件; 每輪結束後)，跟 JS 一樣。
  • #define NAME 值 是純文字替換：前置處理器在編譯前把 KM_END 換成 50。它沒有型別，也不佔記憶體。行尾不加分號，加了分號也會一起被替換進去。
  • 慣例是常數名稱全部大寫。
  • K&R 是 C89 標準，迴圈變數要在 for 前面宣告。上面把 int km 寫在 for 裡面是 C99 之後的寫法，現代的 gcc 預設就支援。
韌體連結：韌體程式碼裡的 #define 多到數不完，例如 #define PCI_VENDOR_ID_OFFSET 0x00、#define BIT3 0x08。EDK II 也大量用巨集來定義暫存器位址和旗標。

1.5Character Input and Output

這是第一章份量最重的一節：用 getchar() 和 putchar() 一次處理一個字元，寫出複製、計數、數行、數字數四個小工具。

核心慣用寫法：一直讀到 EOF

#include <stdio.h>

int main(void)
{
    int c;                              // ⚠ 用 int，不是 char！

    while ((c = getchar()) != EOF)      // 讀一個字元，順便判斷是否結束
        putchar(c);
    return 0;
}
  • 為什麼 c 是 int：EOF（end of file）是一個特殊值，通常是 -1。它必須跟所有正常字元都不一樣，所以要用比 char 更大的型別來裝。
  • 賦值本身是一個運算式：(c = getchar()) 的值就是剛讀到的字元，所以可以直接拿來跟 EOF 比較。
⚠ 括號不能省：c = getchar() != EOF 會先算 !=，所以 c 只會得到 0 或 1。運算子優先順序是第 2 章的主題，這裡先記住「賦值要加括號」。

計數：字元、行數、tab

#include <stdio.h>

int main(void)
{
    int c;
    long chars = 0, lines = 0, tabs = 0;

    while ((c = getchar()) != EOF) {
        ++chars;
        if (c == '\n') ++lines;     // 'x' 是字元常數，本質就是一個整數（ASCII 碼）
        if (c == '\t') ++tabs;
    }
    printf("chars=%ld lines=%ld tabs=%ld\n", chars, lines, tabs);
    return 0;
}
  • '\n' 的值是整數 10。在 C 裡字元就是小整數，可以直接比較，也可以做加減，例如 c - '0' 能把字元 '7' 轉成數字 7。
  • ++x 是遞增，long 是範圍比較大的整數，印出時用 %ld。
  • 要區分 ==（比較）和 =（賦值）。把 if (c = '\n') 寫錯成賦值，條件會永遠成立。開啟 -Wall 時編譯器會警告。

數字數：用一個「狀態」變數

書上的字數統計是個小型狀態機：記住自己目前在單字裡面還是外面，從外面進到裡面時就把字數加一。

int c, in_word = 0;
long words = 0;

while ((c = getchar()) != EOF) {
    if (c == ' ' || c == '\n' || c == '\t')
        in_word = 0;                  // 遇到空白，離開單字
    else if (!in_word) {
        in_word = 1;                  // 從外面進入單字的那一刻才計數
        ++words;
    }
}
  • || 是 OR，&& 是 AND，兩者都會短路求值，跟 JS 一樣。
  • C89 沒有 bool 型別，用 int 表示：0 是假，非 0 就是真。
韌體連結：「每次讀一個字元，用狀態變數決定下一步」正是韌體解析 UART 序列輸入、處理 debug console 指令的方式。狀態機也是韌體最常見的設計模式之一。

1.6Arrays

用陣列一次統計很多種類別。書上統計的是數字、空白和其他字元，這裡改成統計十六進位數字。

#include <stdio.h>

int main(void)
{
    int c;
    int hex[16];                        // 固定大小，宣告後不能變長

    for (int i = 0; i < 16; ++i)
        hex[i] = 0;                     // ⚠ 區域陣列不會自動清 0，一定要自己初始化

    while ((c = getchar()) != EOF) {
        if (c >= '0' && c <= '9')
            ++hex[c - '0'];             // 用字元算出陣列索引
        else if (c >= 'a' && c <= 'f')
            ++hex[c - 'a' + 10];
    }
    for (int i = 0; i < 16; ++i)
        printf("%X: %d\n", i, hex[i]);  // %X 以大寫十六進位印出
    return 0;
}
  • 陣列大小固定，索引從 0 開始。C 不像 JS 的 array 可以 push。
  • C 不檢查越界：寫入 hex[16] 不會報錯，而是默默蓋掉旁邊的記憶體。這是 C 最危險的特性之一，也是很多資安漏洞的根源。
  • 沒初始化的區域變數裡面是垃圾值，也就是那塊記憶體原本殘留的內容，不會是 0。
  • if … else if … else 是多路分支，跟 JS 一樣。
韌體連結：韌體裡沒有可以自動長大的陣列，也通常沒有 malloc（後端的 heap 在這裡很稀缺）。資料結構大多是固定大小的陣列或 buffer，越界寫入可能讓整台機器開不了機。

1.7–1.8Functions 與 Call by Value

把邏輯包成函式，並理解 C 的參數一律傳值。

#include <stdio.h>

int clamp(int x, int lo, int hi);       // 函式原型（prototype）：先宣告，定義寫在後面
void try_swap(int a, int b);

int main(void)
{
    printf("%d\n", clamp(150, 0, 100)); // 100

    int x = 1, y = 2;
    try_swap(x, y);
    printf("x=%d y=%d\n", x, y);        // 還是 x=1 y=2！
    return 0;
}

int clamp(int x, int lo, int hi)
{
    if (x < lo) return lo;
    if (x > hi) return hi;
    return x;
}

void try_swap(int a, int b)             // a、b 只是複本，改了不影響呼叫端
{
    int tmp = a;
    a = b;
    b = tmp;
}
  • 函式原型：C 編譯器由上往下讀，呼叫函式之前必須先看過它的宣告。原型通常放在 .h 標頭檔裡。
  • void 代表沒有回傳值。
  • 傳值（call by value）：參數是一份複本，所以上面的 try_swap 換不了。真的要交換，必須把變數的位址傳進去，這要等到第 5 章的指標。
  • 例外是陣列：把陣列當參數傳時，傳過去的是它開頭的位址，所以函式可以修改呼叫端陣列的內容。這是第 5 章的伏筆。
韌體連結：UEFI API 幾乎全靠「傳指標進去，讓函式把結果寫回來」，回傳值只拿來表示狀態（EFI_STATUS）。例如 gBS->LocateProtocol(&Guid, NULL, (VOID **)&Proto)。只要理解了傳值，就能理解為什麼要這樣寫。

1.9Character Arrays：C 的「字串」

C 沒有 string 型別。字串就是一個 char 陣列，最後放一個 '\0'（值為 0）當作結束記號。

#include <stdio.h>

#define MAX_LINE 256

int read_line(char buf[], int max);     // 回傳讀到的長度，0 代表 EOF

int main(void)
{
    char line[MAX_LINE];
    int len;

    while ((len = read_line(line, MAX_LINE)) > 0)
        printf("[%3d] %s", len, line);  // %s 會一直印，直到遇到 '\0'
    return 0;
}

int read_line(char buf[], int max)
{
    int c, i = 0;

    while (i < max - 1 && (c = getchar()) != EOF && c != '\n')
        buf[i++] = c;                   // 保留最後一格給 '\0'
    if (c == '\n')
        buf[i++] = c;
    buf[i] = '\0';                      // ⚠ 沒有這行，%s 會一路印到記憶體深處
    return i;
}
  • "abc" 在記憶體裡實際上是 4 個 byte：'a' 'b' 'c' '\0'。所以 buffer 大小要比內容多一格。
  • C 的字串不知道自己有多長，要從頭數到 '\0' 才知道。這就是 strlen 的做法。
  • max - 1 的檢查是在防止緩衝區溢位。少了它，輸入一行很長的文字就會寫出陣列的邊界。
  • 書上這一節的自訂函式叫 getline，會跟現代 glibc 裡的同名函式衝突，所以這裡改名叫 read_line。
韌體連結：UEFI 的字串是 UCS-2 寬字元（CHAR16），字串常數要寫成 L"Hello"，但同樣以 0 結尾。BIOS Setup 畫面的字串、UEFI variable 的名稱，用的都是這套規則。

1.10External Variables and Scope

函式內的變數只活在那個函式裡。宣告在所有函式外面的變數是外部變數（也就是全域變數），所有函式都能存取。

/* counter.c */
int g_error_count = 0;          // 定義（definition）：真的配置記憶體，只能有一處

void report_error(void) { ++g_error_count; }

/* main.c */
#include <stdio.h>
extern int g_error_count;       // 宣告（declaration）：「這個變數在別的檔案裡」
void report_error(void);

int main(void)
{
    report_error();
    report_error();
    printf("%d\n", g_error_count);  // 2
    return 0;
}
# 多個檔案一起編譯
gcc -Wall main.c counter.c -o app
  • 自動變數（automatic）：函式內的區域變數，函式回傳後就消失，每次呼叫重新建立。
  • 外部變數：整個程式執行期間都存在，可以跨函式、跨檔案共用。
  • 定義和宣告的差別：定義會配置記憶體，整個程式只能有一處；宣告只是告訴編譯器「它存在」，可以有很多處。extern 是宣告。這個區分在 C 裡非常重要，到第 4 章會講得更詳細。
  • 書上也提醒：全域變數方便，但會讓程式之間的相依關係變得難以追蹤，要節制使用。這跟後端避免全域狀態的道理一樣。
韌體連結：EDK II 有一批大家都會用的全域變數：gBS（Boot Services）、gRT（Runtime Services）、gST（System Table）。它們都是用 extern 宣告在標頭檔裡，而且一開始就會碰到。

自我檢查

先自己回答再點開答案。全部答得出來，就可以進第 2 章。

1. int x = 7 / 2; 和 float y = 7 / 2; 的值各是多少？兩個都是 3（y 是 3.0）。7 / 2 兩邊都是整數，所以先做整數除法得到 3，之後才轉成 float。要得到 3.5，得寫 7.0 / 2。
2. 為什麼 getchar() 的結果要存在 int，不能存在 char？因為 EOF 必須和所有合法字元都不同，通常是 -1。char 的範圍裝不下「所有字元再加上 EOF」，用 char 可能會把某個正常字元誤判成 EOF，或者永遠等不到 EOF。
3. char s[5] = "hello"; 有什麼問題？"hello" 需要 6 個 byte，因為後面還有一個 '\0'。陣列只有 5 格，結尾的 '\0' 放不進去，之後用 %s 印出或呼叫 strlen 時，會一路讀到陣列外面的記憶體。
4. 寫一個 void add_one(int n) { n = n + 1; }，呼叫 add_one(x) 之後 x 會變嗎？不會。C 一律傳值，n 只是 x 的複本。要讓函式改到 x，必須傳 &x，函式參數改成 int *n，這是第 5 章的內容。
5. #define SIZE 10;（結尾有分號）會出什麼問題？#define 是純文字替換，分號也會被一起貼上。例如 int a[SIZE]; 會變成 int a[10;];，造成編譯錯誤；放在運算式裡的話，可能產生更難察覺的 bug。
6. 外部變數的「定義」和「宣告」差在哪？定義會配置記憶體，整個程式只能有一處，例如 int g = 0;。宣告只是告訴編譯器「這個變數存在、型別是什麼」，可以出現很多次，例如 extern int g;。
7. 寫入 arr[10]（陣列只有 10 格）時，C 會怎麼處理？不會報錯，也不會拋出例外，而是直接寫進陣列後面的記憶體。結果可能看起來正常，也可能蓋掉其他變數，或讓程式崩潰。這種行為叫 undefined behavior。開發時可以用 gcc -fsanitize=address 抓這類錯誤。

2.1–2.2變數名稱、資料型別與大小

C 的整數型別大小不是固定的，標準只規定最小範圍，實際大小由編譯器和 CPU 決定。這是寫韌體前一定要先搞懂的事。

變數名稱（2.1）

  • 名稱由字母、數字、底線組成，不能以數字開頭，而且大小寫有別。
  • 不要用底線開頭的名稱，那些保留給函式庫和編譯器使用。
  • 慣例是變數用小寫，常數（#define）用全大寫。

基本型別（2.2）

型別標準保證常見大小（x86-64／ARM64 Linux）用途
char至少 8 bit1 byte字元、單一 byte。有沒有號由平台決定
short至少 16 bit2 bytes小範圍整數
int至少 16 bit4 bytesCPU 最自然的整數大小
long至少 32 bit8 bytes（Windows 是 4）大範圍整數
float／double由實作決定4／8 bytes浮點數（韌體少用）
  • signed（有號）可以存負數。unsigned（無號）只存 0 以上的數，範圍是有號的兩倍，而且溢位時會繞回 0，這是標準保證的行為。
  • 有號整數溢位是 undefined behavior：結果不保證，編譯器最佳化時甚至可能假設它不會發生。
  • 各型別的實際範圍定義在 <limits.h>（例如 INT_MAX），浮點數的定義在 <float.h>。
#include <stdio.h>
#include <limits.h>
#include <stdint.h>

int main(void)
{
    printf("char  %zu byte,  %d ~ %d\n", sizeof(char), CHAR_MIN, CHAR_MAX);
    printf("int   %zu bytes, %d ~ %d\n", sizeof(int), INT_MIN, INT_MAX);
    printf("long  %zu bytes\n", sizeof(long));
    printf("unsigned int max = %u\n", UINT_MAX);

    unsigned int u = UINT_MAX;
    u = u + 1;                                // 無號溢位：保證繞回 0
    printf("UINT_MAX + 1 = %u\n", u);

    uint32_t reg = 0xDEADBEEF;                // 固定 32 bit，到哪個平台都一樣
    printf("reg = 0x%08X (%zu bytes)\n", (unsigned)reg, sizeof reg);
    return 0;
}

在 x86-64 Ubuntu 上，CHAR_MIN 是 -128；在 Fusion 的 ARM64 Ubuntu 上是 0，因為 ARM64 Linux 的 char 預設是無號的。（但 Mac 本機雖然也是 ARM64，macOS 卻規定 char 有號，所以會是 -128。決定這件事的是平台的 ABI，不只是 CPU。）兩台機器都跑一次，就能親眼看到「由平台決定」是什麼意思。

韌體連結：韌體程式碼不會直接用 int、long 來表示暫存器，因為大小會隨平台改變。一般 C 程式用 <stdint.h> 的 uint8_t、uint32_t、uint64_t。EDK II 有自己的一套：UINT8、UINT32、UINT64，還有 UINTN（跟 CPU 原生寬度一樣，64 位元機器上就是 64 bit）。K&R 是 1988 年的書，那時候還沒有 stdint.h，C99 才加進標準。

2.3常數

同一個數字有很多種寫法，韌體裡最常用的是十六進位。

#include <stdio.h>

enum power_state { S0, S3 = 3, S4, S5 };     // S0=0, S3=3, S4=4, S5=5

int main(void)
{
    unsigned int a = 255;          // 十進位
    unsigned int b = 0xFF;         // 十六進位：0x 開頭
    unsigned int c = 0377;         // ⚠ 八進位：0 開頭！不是 377
    printf("%u %u %u\n", a, b, c);             // 255 255 255

    unsigned long big = 4000000000UL;          // U = unsigned，L = long
    printf("%lu\n", big);

    char nl = '\n', esc = '\x1B', nul = '\0';  // 字元常數：跳脫寫法、十六進位寫法
    printf("%d %d %d\n", nl, esc, nul);        // 10 27 0

    printf("%s\n", "split " "string");         // 相鄰字串常數會在編譯時自動接起來
    printf("sleep state = %d\n", S3);
    return 0;
}
  • 整數常數：0x 開頭是十六進位，0 開頭是八進位，所以 010 等於 8。這個設計常讓人踩坑，例如寫 int code = 0123; 的時候。
  • 後綴：U 表示 unsigned，L 表示 long，UL 兩者都是。寫大數字或做位元運算時，加上 U 可以避免有號數的問題。
  • 字元常數：'A' 的值是 65。除了 '\n' 這類跳脫字元，也可以用 '\x41'（十六進位）或 '\101'（八進位）直接寫出數值。
  • 字串常數："abc" 會自動在最後加上 '\0'，所以 "x"（2 bytes）和 'x'（一個整數）是兩回事。
  • 列舉 enum：一組有名字的整數常數。沒有指定值時從 0 開始，每個加 1；中途指定值後，從那個值繼續往下加。跟 #define 比起來，enum 在 debugger 裡看得到名字。
韌體連結：翻開任何韌體原始碼，滿滿都是 0x，例如 #define PCI_COMMAND_OFFSET 0x04、MmioWrite32(0xFED00000, 0x1)。I/O port、記憶體位址、暫存器值幾乎都用十六進位表示，因為一個十六進位數字剛好對應 4 個 bit，很容易換算成二進位。

2.4宣告與 const

int count = 0, limit = 100;        // 宣告時就初始化
const double ratio = 0.62;         // const：之後不能再修改
const char banner[] = "BOOT";      // 陣列大小由初始值決定（5，含 '\0'）

int length(const char s[]);        // 承諾這個函式不會改動 s 的內容
  • 變數可以在宣告時初始化。外部變數和 static 變數沒有初始化時會自動是 0，但函式內的區域變數不會（第一章提過的垃圾值）。
  • const 表示「這個值不應該被修改」，修改時編譯器會報錯。用在函式參數上，可以讓呼叫端知道函式不會改它傳進去的陣列。
韌體連結：跟 const 同一類的修飾詞還有 volatile，K&R 只在附錄稍微提到，但韌體很常用。volatile 告訴編譯器：「這個值隨時可能被硬體改掉，每次都要真的去讀，不要用快取的舊值」。讀寫硬體暫存器時一定要加。

2.5–2.6算術、關係與邏輯運算子

int a = 17, b = 5;
a / b;           // 3   整數除法，小數捨去
a % b;           // 2   餘數（只能用在整數）
-17 / 5;         // -3  C99 起規定往 0 的方向捨去
-17 % 5;         // -2  餘數的正負號跟被除數一樣

(a > b) + (a == b);    // 1   比較結果就是 int：成立是 1，不成立是 0
!a;                    // 0   a 不是 0，所以 !a 是 0
(b != 0 && a / b > 2); // && 短路：b 是 0 就不會做除法
  • % 取餘數。常見用途：判斷奇偶（n % 2）、環狀 buffer 的索引繞回（(i + 1) % SIZE）、判斷是否對齊。
  • 關係運算子（> >= < <= == !=）和邏輯運算子（&& || !）的結果都是 int 的 0 或 1，不是布林型別。
  • && 和 || 會從左算到右，一確定結果就停下來。所以「先檢查、再使用」的寫法是安全的，例如 i < max && buf[i] != '\0'。

實驗：如果把 b 改成 0？

只有 a / b 和 a % b 兩行會出問題：整數除以 0 是 undefined behavior，標準沒有規定結果。其他幾行照常運作，最後一行正好示範了「先檢查再除」為什麼安全。下面是 int a = 17, b = 0; 在 Mac 上實測的結果（程式在 C/ch2/div0.c）：

  • ARM64 沒開最佳化：看起來沒事。ARM 的除法指令遇到除以 0 時，硬體規定直接回傳 0，不會報錯；% 是用 a - (a/b)*b 算的，所以得到 17。bug 被藏起來，是最危險的情況。
  • ARM64 開 -O2：印出亂數。編譯器假設程式不會發生 undefined behavior，可以隨意產生程式碼，結果就是記憶體裡剩下的某個值。
  • x86-64：程式崩潰，exit code 136（128 + 8，也就是 SIGFPE）。x86 的除法指令遇到除以 0 會觸發硬體例外，Linux 上會顯示 Floating point exception，雖然這其實是整數除法。
⚠ 編譯器不會警告，-Wall -Wextra 都沒有反應，因為 b 是變數，編譯時看不出它會是 0。要用 UndefinedBehaviorSanitizer 在執行時抓： 
gcc -std=c11 -g -fsanitize=undefined div0.c -o div0 && ./div0
# div0.c:5:41: runtime error: division by zero
用 serve.sh 的話預設就會開啟：./serve.sh ch2/div0.c。

對照：浮點數除以 0 不一樣。17.0 / b 會得到 inf（無限大），這是 IEEE 754 明確定義的結果，不是 undefined behavior。

韌體連結：韌體裡的除數常常來自硬體暫存器或感測器讀值，例如用頻率算週期、用計數算平均。硬體還沒準備好、讀到 0 的時候，在 x86 平台上就是整台機器開機時當掉。所以任何除法之前，都要先確認除數不是 0，就像上面最後一行那樣。
韌體連結：判斷位址有沒有對齊時，通常不用 %，而是用位元運算：(addr & 0xFFF) == 0 就表示對齊 4 KB。原因是 % 要做除法，比較慢；而且大小剛好是 2 的次方時，兩種寫法結果相同。

2.7型別轉換

不同型別的值放在一起運算時，C 會自動轉型，而且不會提醒你。這是最容易出現隱藏 bug 的一節。

自動轉換的基本規則

  • 整數提升：比 int 小的型別（char、short）在運算前會先轉成 int。
  • 往「比較大」的型別靠攏：int 和 double 運算時，int 會先轉成 double；int 和 long 運算時，會轉成 long。
  • 有號和無號混在一起時，有號數會被轉成無號，這是最大的坑，看下面的例子。
  • 大轉小會被截斷：把 int 存進 char，只會留下最低的 8 bit。
#include <stdio.h>

int main(void)
{
    int neg = -1;
    unsigned int one = 1;
    if (neg < one)                       // ⚠ -1 被轉成 unsigned，變成 4294967295
        printf("expected\n");
    else
        printf("surprise: -1 >= 1u\n");  // 實際會印這行（-Wextra 會警告）

    int big = 300;
    unsigned char small = big;           // 截斷：300 = 0x12C，只留下 0x2C
    printf("%d\n", small);               // 44

    int total = 7, n = 2;
    double avg1 = total / n;             // 3.0：先做整數除法，才轉 double
    double avg2 = (double)total / n;     // 3.5：強制轉型（cast）
    printf("%.1f %.1f\n", avg1, avg2);

    char digit = '7';
    int value = digit - '0';             // 字元轉數字：'7' - '0' = 7
    printf("%d\n", value);
    return 0;
}
  • 強制轉型（cast）：(type)運算式，明確告訴編譯器要轉成什麼型別。
  • 字元和數字互轉：c - '0'，或判斷大小寫的 c >= 'a' && c <= 'z'，依賴的是字元的編碼順序。標準函式庫 <ctype.h> 也有現成的 isdigit、isupper、tolower 可以用。
  • char 有沒有號由平台決定：把 char 裡大於 127 的值轉成 int，在 x86 上會變成負數，在 ARM 上不會。所以處理二進位資料時要明確用 unsigned char 或 uint8_t。
韌體連結：韌體裡到處都是「把 64 bit 位址轉成 32 bit」或「從 byte 陣列組出 32 bit 整數」這類操作，例如 (UINT32)(Address & 0xFFFFFFFF)。截斷和符號延伸（sign extension）出錯時，通常不會當機，而是讀到錯誤的位址，這種 bug 非常難查。

2.8遞增與遞減運算子

int n = 5, x;
x = n++;     // 後置：先取值再加 1 → x = 5，n = 6
x = ++n;     // 前置：先加 1 再取值 → x = 7，n = 7

單獨寫 n++; 和 ++n; 的效果一樣。只有在運算式中使用它的值時才有差別。最常見的慣用寫法是一邊讀、一邊寫：

/* 就地刪除字串中的所有空白：i 負責讀，j 負責寫 */
void strip_spaces(char s[])
{
    int i, j;
    for (i = j = 0; s[i] != '\0'; i++)
        if (s[i] != ' ')
            s[j++] = s[i];      // 寫入 s[j] 之後，j 才加 1
    s[j] = '\0';                // 記得補上結尾
}
⚠ 同一個運算式裡不要對同一個變數 ++ 兩次，也不要一邊 ++ 一邊讀它。例如 i = i++; 或 a[i] = i++; 都是 undefined behavior，不同編譯器的結果可能不同（見 2.12）。
韌體連結：*dst++ = *src++ 這種寫法（第 5 章會學到）是韌體裡複製 buffer 最常見的樣子，所以前置和後置的差別要非常熟。

2.9位元運算子 ⭐

對韌體工程師來說，這是整本書最重要的一節。設定硬體幾乎就等於讀寫暫存器裡的某幾個 bit。

運算子名稱範例（8 bit）常見用途
&AND1100 1010 & 0000 1111 = 0000 1010取出某幾個 bit（遮罩）、清掉 bit
|OR1100 0000 | 0000 0101 = 1100 0101把 bit 設成 1
^XOR1100 1010 ^ 0000 1111 = 1100 0101翻轉 bit、比較差異
~NOT（補數）~0000 1111 = 1111 0000做出「除了這幾個 bit 以外」的遮罩
<<左移0000 0001 << 3 = 0000 1000做出第 n 個 bit 的遮罩；乘以 2ⁿ
>>右移1000 0000 >> 4 = 0000 1000把某段 bit 移到最右邊再取出；除以 2ⁿ
⚠ 不要把 & 和 && 搞混：6 & 1 是 0（逐位元 AND），6 && 1 是 1（兩邊都不是 0）。

四個基本操作：設定、清除、翻轉、測試

#include <stdio.h>
#include <stdint.h>

#define BIT(n)  (1u << (n))          // 第 n 個 bit 的遮罩；用 1u 而不是 1

/* 假想的控制暫存器：bit0 = 啟用，bit3 = 中斷，bit[7:4] = 速度等級 */
#define CTRL_ENABLE      BIT(0)
#define CTRL_IRQ         BIT(3)
#define CTRL_SPEED_SHIFT 4
#define CTRL_SPEED_MASK  (0xFu << CTRL_SPEED_SHIFT)

static void print_bin8(uint8_t v)
{
    for (int i = 7; i >= 0; i--)
        putchar((v & BIT(i)) ? '1' : '0');
    putchar('\n');
}

int main(void)
{
    uint8_t ctrl = 0;

    ctrl |= CTRL_ENABLE;                  // 設定：OR 上遮罩
    ctrl |= CTRL_IRQ;
    print_bin8(ctrl);                     // 00001001

    ctrl &= (uint8_t)~CTRL_IRQ;           // 清除：AND 上「反轉後的遮罩」
    print_bin8(ctrl);                     // 00000001

    ctrl ^= CTRL_ENABLE;                  // 翻轉：XOR 遮罩
    print_bin8(ctrl);                     // 00000000

    if ((ctrl & CTRL_ENABLE) == 0)        // 測試：AND 後看是不是 0（括號不能少）
        printf("disabled\n");

    /* 寫入一個多 bit 欄位：先清掉舊值，再放入新值 */
    unsigned speed = 5;
    ctrl = (ctrl & ~CTRL_SPEED_MASK) | ((speed << CTRL_SPEED_SHIFT) & CTRL_SPEED_MASK);
    print_bin8(ctrl);                     // 01010000

    /* 讀出多 bit 欄位：先遮罩，再右移 */
    printf("speed = %u\n", (ctrl & CTRL_SPEED_MASK) >> CTRL_SPEED_SHIFT);  // 5
    return 0;
}

逐行解析：這段程式在做什麼

它在模擬韌體最常做的一件事：讀寫硬體暫存器裡的某幾個 bit。先假想一個 8 bit 的控制暫存器，再示範設定、清除、翻轉、測試，以及讀寫多 bit 欄位。

① 假想的暫存器長這樣

bit:    7   6   5   4   3   2   1   0
      ┌───┬───┬───┬───┬───┬───┬───┬───┐
      │ speed（4 bit）│IRQ│ - │ - │EN │
      └───┴───┴───┴───┴───┴───┴───┴───┘

bit 0 是 ENABLE（啟用），bit 3 是 IRQ（中斷），bit 7–4 是 SPEED（速度等級，4 個 bit，可以存 0–15）。真實的硬體規格書（datasheet）就是用這種表格描述每個暫存器的。

疑問 1：那 bit 1 跟 bit 2 是做什麼的？

在這個假想的暫存器裡，bit 1 和 bit 2 沒有任何用途，圖上畫成 - 就是這個意思。不過這種「沒用到的 bit」在真實硬體裡非常普遍，規格書裡叫 Reserved（保留位），而且有一套處理規則：

Bit名稱說明
7:4SPEED速度等級
3IRQ_EN中斷啟用
2:1Reserved讀取值不保證；寫入時必須保持原值
0EN啟用
  • 常見的兩種標示（PCIe 規格的用語）：RsvdP（Reserved, Preserve）表示寫入時要保留原本讀到的值；RsvdZ（Reserved, Zero）表示寫入時一律寫 0。
  • 保留的原因：留給未來的晶片版本擴充（新一代可能把 bit 1 定義成新功能，舊韌體不能亂改它），或者是廠商內部測試用（亂寫可能造成無法預期的行為）。

這就是為什麼要用 |=、&=，而不是直接賦值。假設暫存器目前是 0000 0110（bit 1、2 是 1，硬體有它自己的用途），你想打開 ENABLE：

ctrl = CTRL_ENABLE;      // ❌ 結果是 0000 0001：bit 1、2 被清成 0 了
ctrl |= CTRL_ENABLE;     // ✅ 結果是 0000 0111：只改 bit 0，bit 1、2 保持原樣

|=、&= ~、^= 都會先讀出原本的值，只改遮罩指定的 bit，再寫回去。這叫 read-modify-write（讀－改－寫），會自動保留所有沒碰到的 bit，包括保留位。後面 ⑤ 寫入 SPEED 欄位的公式也一樣：ctrl & ~CTRL_SPEED_MASK 只清掉 bit 7–4，bit 3–0（包含 bit 1、2）原封不動地帶過去。

真實例子：PCIe 的 Command 暫存器（config space offset 0x04，16 bit），是韌體最常碰到的暫存器之一：

Bit名稱
0I/O Space Enable
1Memory Space Enable
2Bus Master Enable
3–9其他控制位（Special Cycles、Parity Error Response、SERR# Enable 等）
10Interrupt Disable
15:11Reserved

BIOS 要讓一張 PCIe 卡可以存取記憶體時，寫法跟這一節的範例一模一樣：

cmd = PciRead16(dev, 0x04);
cmd |= BIT(1) | BIT(2);          // 打開 Memory Space 和 Bus Master
PciWrite16(dev, 0x04, cmd);      // 其他 bit（包含保留位）都保持原值寫回
小練習：把 bit 1、2 定義成一個 2 bit 的「模式」欄位（0–3），照 SPEED 的寫法自己寫一次讀和寫，並驗證設定 MODE 時，SPEED 和 ENABLE 都不會被改到。 
#define CTRL_MODE_SHIFT 1
#define CTRL_MODE_MASK  (0x3u << CTRL_MODE_SHIFT)   // 0000 0110

疑問 2：IRQ 的全名是什麼？

IRQ 是 Interrupt Request，中文叫「中斷請求」。硬體裝置有事情要 CPU 處理時（網卡收到封包、鍵盤被按下、磁碟讀完資料），就發出一個中斷請求。CPU 會暫停手上的工作，先去執行對應的處理程式（interrupt handler），處理完再回到原本的工作。

方式硬體世界後端世界的類比
輪詢（polling）CPU 一直去讀裝置的狀態暫存器：「好了沒？好了沒？」前端每秒打一次 API 問結果
中斷（interrupt）裝置做完了主動通知 CPUWebhook：事情發生時由對方主動呼叫你

中斷的好處是 CPU 不用一直空轉去問；代價是處理程式要寫得很小心。它會在任何時間點打斷正在執行的程式，所以會有後端常見的那類 race condition 問題。

在這個範例裡，CTRL_IRQ（bit 3）可以理解成「中斷啟用」開關：設成 1 時，裝置有事情會發出中斷；設成 0 時不發中斷，CPU 要自己輪詢狀態。真實的暫存器常命名得更明確，例如 IRQ_EN、INT_ENABLE，或像 PCIe Command 暫存器的 bit 10，反過來叫 Interrupt Disable（設成 1 是關閉中斷）。

韌體圈會碰到的相關名詞：

  • IRQ 編號：早期 PC 用 IRQ 0–15 區分裝置，例如 IRQ 0 是計時器、IRQ 1 是鍵盤。Linux 的 /proc/interrupts 還看得到這些編號。
  • PIC／APIC：把各裝置的中斷集中起來送給 CPU 的中斷控制器。PIC 是舊式的，現代 x86 用 APIC。
  • MSI／MSI-X：PCIe 裝置現在的中斷方式，用「寫入一個特定的記憶體位址」取代實體的中斷線。
  • ACPI 的 _PRT：BIOS 透過 ACPI table 告訴作業系統「哪個 PCI 裝置接到哪條中斷線」，屬於階段 2 ACPI 主題的內容。
韌體連結：UEFI 韌體本身幾乎不用裝置中斷。UEFI 規格只用計時器中斷，其他裝置 driver 都是用輪詢加上計時器事件來運作；等作業系統開機之後，才會全面改用中斷。所以階段 2 寫 UEFI driver 時主要會寫輪詢，中斷處理要到 Linux driver 或 BMC 韌體時才會碰到。

② 巨集：把 bit 位置變成「遮罩」

BIT(n) 把 1 往左移 n 格，做出「只有第 n 個 bit 是 1」的數字，這就是遮罩（mask）：

巨集計算二進位
CTRL_ENABLE = BIT(0)1 << 00000 0001
CTRL_IRQ = BIT(3)1 << 30000 1000
CTRL_SPEED_MASK0xF << 41111 0000
  • 為什麼寫 1u 不寫 1：1 是有號的 int，1 << 31 會移進正負號位元，是 undefined behavior。u 代表無號數，位移的結果有明確定義。
  • 為什麼 (n) 要加括號：巨集是純文字替換。參數一律加括號，展開後才不會被周圍運算子的優先順序打亂，這是保險的習慣。
  • CTRL_SPEED_SHIFT 4 記錄「速度欄位從第 4 個 bit 開始」，讀和寫的時候都會用到。

③ print_bin8：把 8 bit 印成 0 和 1

從最高位（bit 7）檢查到最低位（bit 0）：v & BIT(i) 只留下第 i 個 bit，結果不是 0 就印 '1'，是 0 就印 '0'。這就是習題建議裡提到的 print_bin() 小工具。

④ 主程式逐步追蹤

設定 bit：|=（OR）。OR 的規則是「有 1 就是 1」，所以只會打開遮罩上的那個 bit，其他 bit 不受影響。

ctrl          0000 0000
| CTRL_ENABLE 0000 0001
= ctrl        0000 0001
| CTRL_IRQ    0000 1000
= ctrl        0000 1001   ← 印出 00001001

清除 bit：&= ~遮罩（AND 上反轉後的遮罩）。AND 的規則是「兩邊都 1 才是 1」。反轉後的遮罩只有 bit 3 是 0，所以只有 bit 3 被清掉，其他 bit 保持原樣。

~CTRL_IRQ     1111 0111   ← 先把遮罩反轉：除了 bit 3 全是 1
ctrl          0000 1001
& ~CTRL_IRQ   1111 0111
= ctrl        0000 0001   ← 印出 00000001

(uint8_t) 這個 cast 的原因：~CTRL_IRQ 其實是 32 bit 的無號數 0xFFFFFFF7，比 uint8_t 大。先轉成 8 bit 再運算，意思比較清楚，也避免開啟較嚴格的警告選項時被編譯器提醒。

翻轉 bit：^=（XOR）。XOR 的規則是「不同才是 1」。遮罩上是 1 的位置會被翻轉，其他位置不變；再做一次就會翻回來。

ctrl          0000 0001
^ CTRL_ENABLE 0000 0001
= ctrl        0000 0000   ← 印出 00000000

測試 bit：(ctrl & 遮罩) == 0。ctrl & CTRL_ENABLE 只留下 bit 0，結果是 0 代表沒啟用，所以印出 disabled。括號不能少：== 的優先順序比 & 高，寫成 ctrl & CTRL_ENABLE == 0 會變成 ctrl & 0，結果永遠是 0（見 2.12 的陷阱 1）。

⑤ 寫入多 bit 欄位：先清舊值，再放新值

把 ctrl = (ctrl & ~CTRL_SPEED_MASK) | ((speed << CTRL_SPEED_SHIFT) & CTRL_SPEED_MASK); 拆成三步看（speed = 5，二進位 0101）：

步驟 A：清掉速度欄位的舊值
  ctrl               0000 0000
  & ~SPEED_MASK      0000 1111
  =                  0000 0000

步驟 B：把新值移到欄位的位置，再用遮罩裁掉多餘的 bit
  speed              0000 0101
  << 4               0101 0000
  & SPEED_MASK       1111 0000
  =                  0101 0000

步驟 C：合併（OR）
  0000 0000 | 0101 0000 = 0101 0000   ← 印出 01010000
  • 為什麼一定要先清掉舊值：如果原本的速度是 1010，直接 OR 上 0101 會得到 1111，數值就錯了。
  • 步驟 B 為什麼還要 & SPEED_MASK：防止 speed 超過 15。例如 speed = 20（10100），左移後會多出一個 bit 跑到欄位外面；遮罩會把它裁掉，避免誤改到旁邊其他的 bit。

⑥ 讀出多 bit 欄位：先遮罩，再右移

ctrl          0101 0000
& SPEED_MASK  1111 0000
=             0101 0000
>> 4          0000 0101  = 5   ← 印出 speed = 5

寫入的步驟反過來：先只留下欄位那幾個 bit，再移回最右邊，就得到原本的數字。

⑦ 跟真實韌體的差別

這裡的 ctrl 只是記憶體裡一個普通變數。真實的暫存器在一個固定的硬體位址上，通常要這樣存取：

volatile uint32_t *ctrl = (volatile uint32_t *)0xFED00000;   // 硬體位址
*ctrl |= CTRL_ENABLE;

volatile 告訴編譯器：每次都要真的去讀寫硬體，不能用快取的舊值，也不能把讀寫最佳化掉。* 是指標，第 5 章會學到。除了這兩點，遮罩和位移的寫法完全一樣。

位移的注意事項

  • 用無號數做位元運算。1 << 31 在 32 bit 的 int 上是 undefined behavior，因為會移進正負號位元；1u << 31 才安全。
  • 位移量不能大於或等於型別的寬度：對 32 bit 的值做 x << 32 也是 undefined behavior。
  • 負數右移的結果由實作決定：大部分平台會補正負號位元（算術右移），但標準沒有保證。這也是要用無號數的原因之一。
  • ~ 會作用在整數提升後的 int 上：~(uint8_t)0x0F 的結果是 int 的 0xFFFFFFF0，不是 0xF0。存回 8 bit 變數時要注意這點，上面範例裡的 (uint8_t) cast 就是在處理它。
韌體連結：這一段基本上就是 BIOS／BMC 的日常工作。例如：打開 PCIe 裝置的 Memory Space 存取，就是把 Command 暫存器（offset 0x04）的 bit 1 設成 1；讀 CPU 的 MSR、設定 GPIO、解析 ACPI 欄位，都是「遮罩加位移」。EDK II 甚至直接提供 BIT0～BIT63 巨集，以及 MmioOr32、MmioAnd32、MmioBitFieldWrite32 這類函式，做的就是上面這些事。

2.10–2.11複合賦值與條件運算式

複合賦值（2.10）

x op= y 等於 x = x op (y)，op 可以是 + - * / % << >> & ^ |。注意右邊會被當成一整個整體：

x *= y + 1;      // 是 x = x * (y + 1)，不是 x = x * y + 1
flags |= MASK;   // 設定 bit 的標準寫法
flags &= ~MASK;  // 清除 bit 的標準寫法

好處是變數名稱只寫一次。像 regs[port * 4 + offset] |= BIT(2); 這種長的寫法，不用重複寫一次左邊，也比較不會打錯。

條件運算式 ?:（2.11）

int hi = (a > b) ? a : b;                        // 取較大值
char hex_char = (d < 10) ? '0' + d : 'A' + d - 10; // 0–15 轉成 '0'–'F'
printf("%s\n", (status == 0) ? "OK" : "FAIL");
  • 條件 ? 值1 : 值2 是一個運算式，可以直接放在賦值右邊或函式參數裡，跟 JS 一樣。
  • 適合用在簡短的二選一。巢狀太多層會很難讀，那時候應該改用 if。

2.12優先順序與求值順序 ⭐

不需要把整張優先順序表背起來，但下面這幾個陷阱一定要記住。不確定的時候就加括號。

優先順序（高 → 低，節錄）運算子
1() [] -> .
2（由右到左）! ~ ++ -- 正負號 *（取值）&（取位址）(type) sizeof
3* / %
4+ -
5<< >>
6< <= > >=
7== !=
8 → 10& → ^ → |（⚠ 都比 == 低）
11 → 12&& → ||

14（由右到左）= += |= 等賦值

三個經典陷阱

/* 陷阱 1：位元運算子的優先順序比 == 低 */
if (status & READY == 0)        // ⚠ 實際上是 status & (READY == 0)，結果永遠是 0
if ((status & READY) == 0)      // ✅ 正確

/* 陷阱 2：位移的優先順序比 + 低 */
x = 1 << n + 1;                 // ⚠ 是 1 << (n + 1)
x = (1 << n) + 1;               // ✅ 想要先位移就要加括號

/* 陷阱 3：求值順序沒有規定 */
printf("%d %d\n", ++n, n);      // ⚠ undefined behavior：兩個參數哪個先算沒有規定
a[i] = i++;                     // ⚠ undefined behavior
  • 優先順序決定運算式「怎麼分組」；求值順序決定「哪一邊先算」。C 只規定了少數幾個運算子的求值順序：&&、||、?:、逗號。其他像 f() + g() 誰先執行，或函式參數的計算順序，都沒有規定。
  • 所以有副作用的寫法（++、賦值、會修改狀態的函式呼叫），不要在同一個運算式裡跟同一個變數混用。
韌體連結：陷阱 1 是韌體裡真實存在的經典 bug：檢查硬體狀態的 bit 時忘了加括號，條件永遠不成立，程式就卡在等待迴圈裡，看起來像硬體沒有回應。開啟 -Wall 時，gcc 會對這種寫法發出 -Wparentheses 警告。

自我檢查

先自己回答再點開答案。全部答得出來，就可以進第 3 章。

1. 為什麼韌體程式碼用 uint32_t 或 UINT32，而不直接用 unsigned int？int 的大小由平台決定，標準只保證至少 16 bit。暫存器是固定寬度的，所以要用保證寬度的型別，程式換到別的平台時行為才不會改變。
2. int x = 010 + 0x10;，x 是多少？24。010 是八進位，等於 8；0x10 是十六進位，等於 16。
3. 寫出三行程式：把變數 reg 的第 5 個 bit 設成 1、清成 0、翻轉。reg |= (1u << 5);
reg &= ~(1u << 5);
reg ^= (1u << 5);
4. 怎麼取出 reg 的 bit[11:8]（4 個 bit 的欄位）？(reg >> 8) & 0xF，先右移 8 位，再用 4 個 1 當遮罩。也可以寫成 (reg & 0xF00) >> 8。
5. if (flags & MASK == MASK) 有什麼問題？== 的優先順序比 & 高，所以實際上算的是 flags & (MASK == MASK)，也就是 flags & 1。正確寫法是 if ((flags & MASK) == MASK)。
6. int a = -1; unsigned b = 1;，a < b 是真還是假？為什麼？假。有號數和無號數比較時，a 會被轉成 unsigned，-1 變成 UINT_MAX（4294967295），所以比 1 大。
7. 為什麼要寫 1u << 31，不寫 1 << 31？1 是有號的 int，在 32 bit 的 int 上左移 31 位會碰到正負號位元，這是 undefined behavior。1u 是無號數，位移的結果有明確定義。
8. x = n++ + n; 的結果是什麼？沒有固定答案。同一個運算式裡既修改 n（n++）又讀取 n，而且兩者的先後沒有規定，所以是 undefined behavior。不同的編譯器或最佳化設定可能得到不同的結果。

  • 區塊裡可以宣告變數，它只在這個區塊內有效。
⚠ 單獨一個分號也是敘述（空敘述），這會造成很難發現的 bug： 
if (status == READY);       // ⚠ 多了分號：if 管的是「空敘述」
    start_device();         // 這行不受 if 控制，永遠會執行

while (i < n);              // ⚠ 同樣的錯：迴圈本體是空的，i 不會變，變成無窮迴圈
    i++;
開啟 -Wall -Wextra 時，編譯器會對 if (...); 發出 -Wempty-body 警告。

3.2–3.3if-else 與 else if

寫法和 JS 一樣，差別在條件的型別：C 的條件可以是任何數值，0 是假，非 0 就是真。

if (n)            // 等於 if (n != 0)，C 程式很常這樣寫
if (!ptr)         // 等於 if (ptr == NULL)（第 5 章）
if (reg & BIT(3)) // 等於 if ((reg & BIT(3)) != 0)：測試 bit 的常見寫法

else if：多路分支

#include <stdio.h>

/* 依溫度決定風扇轉速等級，BMC 的風扇控制就是這種邏輯 */
int fan_level(int temp_c)
{
    if (temp_c >= 85)
        return 3;           // 全速
    else if (temp_c >= 70)
        return 2;
    else if (temp_c >= 50)
        return 1;
    else
        return 0;           // 最低速
}

int main(void)
{
    int temps[] = { 30, 55, 72, 90 };
    for (int i = 0; i < 4; i++)
        printf("%d°C → level %d\n", temps[i], fan_level(temps[i]));
    return 0;
}

條件由上往下檢查，第一個成立的就執行，後面的全部跳過。所以範圍判斷要從大到小（或從小到大）依序排好，順序錯了結果就會錯。

懸空的 else（dangling else）

if (n > 0)
    if (a > b)
        z = a;
else                // ⚠ 縮排看起來屬於外層的 if，實際上屬於最近的內層 if
    z = b;

else 一律跟最近的、還沒配對的 if 配對，縮排不影響編譯器。解法很簡單：巢狀的 if 一律加大括號。-Wall 會用 -Wdangling-else（gcc 是 -Wparentheses）提醒。

if (n > 0) {
    if (a > b)
        z = a;
} else {            // ✅ 有大括號，else 明確屬於外層
    z = b;
}
韌體連結：很多韌體專案的 coding style 規定 if、for 後面一律要加大括號，即使只有一行。EDK II 和 Linux kernel 的規範都有類似要求，原因就是上面這種錯誤，以及之後加第二行時忘了補括號。

3.4switch ⭐

C 的 switch 有兩個跟 JS、C# 不同的地方：只能比對整數常數，以及沒寫 break 就會往下掉。

#include <stdio.h>

/* 模擬 debug console：從 UART 一次讀一個字元當作指令 */
int main(void)
{
    int c, speed = 0, enabled = 0;

    while ((c = getchar()) != EOF) {
        switch (c) {
        case 'e':                       // enable
            enabled = 1;
            printf("enabled\n");
            break;                      // ⚠ 沒有 break 就會繼續執行下一個 case
        case 'd':                       // disable
            enabled = 0;
            printf("disabled\n");
            break;
        case '0': case '1': case '2': case '3': case '4':
        case '5': case '6': case '7': case '8': case '9':
            speed = c - '0';            // 多個 case 共用同一段程式
            printf("speed = %d\n", speed);
            break;
        case '?':
            printf("status: enabled=%d speed=%d\n", enabled, speed);
            break;
        case '\n': case ' ':            // 忽略換行和空白
            break;
        default:                        // 其他所有值
            printf("unknown command '%c'\n", c);
            break;
        }
    }
    return 0;
}
# 存成 ch3/console.c 之後執行
echo "e 5 ? d x" | ./serve.sh ch3/console.c
# enabled / speed = 5 / status: enabled=1 speed=5 / disabled / unknown command 'x'
  • case 後面必須是整數常數：數字、字元常數（'e'）、enum、#define 的常數都可以；字串和變數不行。要比對字串只能用 if 加 strcmp。
  • fall-through（往下掉）：case 只是一個「入口標籤」，進來之後會一路往下執行，直到遇到 break 或 switch 結束。上面 '0'～'9' 共用同一段程式，就是故意利用這個特性。
  • default 處理所有沒列出的值。就算覺得不可能發生，也建議寫上，可以抓到意料之外的輸入。
  • 每個 case 最後都加 break，包括最後一個。之後在下面再加新的 case 時，就不會忘記。
⚠ 忘了 break 是最常見的 switch bug。如果真的要往下掉，寫一行註解說明是故意的，例如 /* fall through */。gcc 和 clang 的 -Wimplicit-fallthrough 會對沒註明的 fall-through 發出警告（gcc 的 -Wextra 會開啟它；C23 起也可以寫 [[fallthrough]];）。
韌體連結：switch 是韌體裡實作狀態機最常見的方式：switch (state) { case STATE_IDLE: … case STATE_WAIT_ACK: … }。UEFI 裡也很常見，例如依 EFI_STATUS 或 PCI class code 決定怎麼處理一個裝置。case 後面配合 enum 使用，可讀性最好。

3.5while、for 與逗號運算子

while 和 for 的寫法跟 JS 一樣。這裡看三個 C 和韌體特有的用法。

逗號運算子：在 for 裡同時更新兩個變數

#include <stdio.h>
#include <stdint.h>

/* 就地反轉 byte 順序：大小端轉換（endianness swap）就是這樣做的 */
void reverse_bytes(uint8_t buf[], int n)
{
    int i, j;
    uint8_t tmp;

    for (i = 0, j = n - 1; i < j; i++, j--) {   // 逗號：兩個變數一起初始化、一起更新
        tmp = buf[i];
        buf[i] = buf[j];
        buf[j] = tmp;
    }
}

int main(void)
{
    uint8_t v[4] = { 0x12, 0x34, 0x56, 0x78 };
    reverse_bytes(v, 4);
    for (int i = 0; i < 4; i++)
        printf("%02X ", v[i]);                   // 78 56 34 12
    printf("\n");
    return 0;
}
  • 逗號運算子從左到右計算每個運算式，整體的值是最右邊那個。實務上幾乎只用在 for 的初始化和更新部分。
  • 注意：函式參數之間的逗號（f(a, b)）和宣告裡的逗號（int i, j;）都只是分隔符號，不是逗號運算子，也不保證計算順序（見 2.12）。

for (;;)：無窮迴圈

for 的三個部分都可以省略，三個都省略就是無窮迴圈，要靠裡面的 break 或 return 離開。for (;;) 和 while (1) 意思完全一樣，韌體的主迴圈常常就是其中一種。

輪詢硬體狀態，一定要加 timeout

/* 等待硬體的 READY bit 變成 1，最多等 MAX_TRIES 次 */
#define READY       BIT(0)
#define MAX_TRIES   1000

int wait_ready(void)
{
    for (int tries = 0; tries < MAX_TRIES; tries++) {
        if (read_status() & READY)
            return 0;               // 成功
        delay_us(10);               // 等一下再問
    }
    return -1;                      // 逾時：回報錯誤，不要永遠卡住
}
韌體連結：這就是上一章 IRQ 問答裡說的「輪詢」，UEFI driver 幾乎都這樣寫。絕對不要寫成 while (!(read_status() & READY));：硬體壞了或沒插好時，整台機器就會卡死在開機畫面，而且看不到任何錯誤訊息。EDK II 裡等待硬體的程式碼，幾乎都有 timeout 參數。（read_status()、delay_us() 是假想的函式，真實環境會是讀取 volatile 暫存器，以及呼叫 gBS->Stall() 或 MicroSecondDelay()。）

3.6do-while

do { … } while (條件); 先執行再檢查，所以至少會執行一次。結尾的分號不能省。

#include <stdio.h>

/* 把無號整數轉成十六進位字串。用 do-while，n = 0 時才會印出 "0" */
void to_hex(unsigned n, char out[])
{
    char tmp[9];
    int i = 0, j = 0;

    do {
        int d = n % 16;
        tmp[i++] = (d < 10) ? '0' + d : 'A' + d - 10;
        n /= 16;
    } while (n > 0);                // 先做一次再判斷

    while (i > 0)                   // 數字是從低位算出來的，要反過來放
        out[j++] = tmp[--i];
    out[j] = '\0';
}

int main(void)
{
    unsigned tests[] = { 0, 255, 0xDEADBEEF };
    char buf[9];
    for (int k = 0; k < 3; k++) {
        to_hex(tests[k], buf);
        printf("0x%s\n", buf);      // 0x0、0xFF、0xDEADBEEF
    }
    return 0;
}

如果改用 while (n > 0) { … }，n 一開始就是 0 時迴圈一次都不會跑，結果會是空字串。這種「至少要做一次」的情況就適合 do-while。

韌體最常見的用法：do { … } while (0) 巨集

/* 想把兩行程式包成一個巨集 */
#define LOG_AND_RESET_BAD(x)   log_error(x); reset_device()           // ❌
#define LOG_AND_RESET(x)       do { log_error(x); reset_device(); } while (0)   // ✅

if (failed)
    LOG_AND_RESET_BAD(code);   // ❌ 展開後只有 log_error 受 if 控制，reset_device 永遠會執行
else
    ...                        // ❌ 甚至會編譯錯誤：else 前面不是 if

if (failed)
    LOG_AND_RESET(code);       // ✅ 整個 do-while 是一個敘述，後面的分號也剛好合法
else
    ...

while (0) 表示只執行一次，所以它不是真的迴圈，只是借用 do-while「把多行包成一個敘述，而且結尾要加分號」的語法特性。

韌體連結：EDK II 的 DEBUG(())、ASSERT() 這類巨集，以及 Linux kernel 裡大量的巨集，都是用 do { … } while (0) 包起來的。第一次看到會覺得奇怪，知道原因之後就會到處看到它。

3.7break 與 continue

break 離開最內層的迴圈或 switch；continue 跳過這一輪剩下的部分，直接進下一輪（continue 只能用在迴圈，不能用在 switch）。

#include <stdio.h>
#include <string.h>

/* 在一段「記憶體」裡每 16 bytes 找一次簽章，
   BIOS 找 SMBIOS 入口點（"_SM_"）、ACPI 的 RSDP（"RSD PTR "）就是這樣找的 */
int find_signature(const unsigned char mem[], int size, const char sig[])
{
    int len = (int)strlen(sig);

    for (int off = 0; off + len <= size; off += 16) {   // 簽章只會出現在 16 byte 對齊的位置
        if (mem[off] != sig[0])
            continue;                   // 第一個字元就不對，直接看下一個位置
        if (memcmp(&mem[off], sig, len) == 0)
            return off;                 // 找到了：用 return 直接離開函式
    }
    return -1;                          // 找完都沒有
}

int main(void)
{
    unsigned char mem[64] = { 0 };
    memcpy(&mem[32], "_SM_", 4);       // 在 offset 32 放一個簽章
    printf("found at %d\n", find_signature(mem, 64, "_SM_"));   // found at 32
    return 0;
}
  • continue 適合用來「先排除不要的情況」，可以減少一層巢狀的 if。
  • 在函式裡找到結果就直接 return，通常比 break 再加一個旗標變數清楚。
  • break 只能離開一層。要從兩層迴圈裡一次跳出來，C 沒有 JS 那種 labeled break，常見做法是包成函式再 return，或者用下一節的 goto。
  • &mem[off] 是「mem[off] 的位址」，第 5 章指標會正式介紹，這裡先當作「從第 off 個 byte 開始」。

3.8goto 與標籤 ⭐

一般教學會說「不要用 goto」，K&R 也說它幾乎都可以避免。但在韌體和 kernel 的 C 程式碼裡，有一種用法是公認的好寫法：錯誤發生時，統一跳到函式結尾清理資源。

#include <stdio.h>
#include <stdlib.h>

/* 依序取得三個資源，任何一步失敗都要把「已經拿到的」釋放掉 */
int load_config(const char *path)
{
    int ret = -1;
    FILE *f = NULL;
    char *buf = NULL, *parsed = NULL;

    f = fopen(path, "r");
    if (f == NULL)
        goto out;                   // 什麼都還沒拿到，直接結束

    buf = malloc(4096);
    if (buf == NULL)
        goto close_file;            // 只要關檔

    parsed = malloc(4096);
    if (parsed == NULL)
        goto free_buf;              // 要釋放 buf，也要關檔

    /* ……正常的處理…… */
    printf("loaded %s\n", path);
    ret = 0;

    free(parsed);
free_buf:                           // 標籤：名稱後面加冒號
    free(buf);
close_file:
    fclose(f);
out:
    return ret;                     // 只有一個出口
}

int main(void)
{
    load_config("README.md");       // loaded README.md（在 C/ 底下執行時，這個檔案存在）
    load_config("no-such-file");    // 開檔失敗，直接回傳 -1
    return 0;
}
  • 標籤的寫法是 名稱:，只在同一個函式內有效，goto 不能跳到別的函式。
  • 標籤由下往上對應「取得資源的順序」：越晚拿到的資源，清理的程式碼放在越上面。所以從哪一步失敗跳進來，就會依反方向一路釋放下去。
  • 如果不用 goto，每個錯誤分支都要自己寫一份清理程式碼，很容易漏掉某個 free 或 fclose，造成資源洩漏。
  • 只往下跳、只用在清理，就是安全的用法。往上跳、拿來代替迴圈，才是一般說的「不要用 goto」。
韌體連結：這個寫法在 Linux kernel 裡到處都是（標籤常命名為 err_free、out_unlock）。EDK II 也很常見，通常寫成「呼叫 Boot Service → if (EFI_ERROR (Status)) { goto Exit; }」，最後在 Exit: 統一用 FreePool() 釋放記憶體、CloseProtocol() 釋放 protocol。後端的 try/finally 或 C++ 的 RAII，在 C 裡就是靠這個模式來做。

自我檢查

先自己回答再點開答案。全部答得出來，就可以進第 4 章。

1. if (x > 0); { x = 0; } 會發生什麼事？if 後面多了分號，控制的是「空敘述」。後面的 { x = 0; } 是一個獨立的區塊，不管條件如何永遠會執行。開啟 -Wall -Wextra 時會有 -Wempty-body 警告。
2. 下面這段的 else 屬於哪個 if？if (a) if (b) f(); else g();屬於內層的 if (b)。else 永遠跟最近的、還沒配對的 if 配對，跟縮排無關。要讓它屬於外層，就要用大括號把內層的 if 包起來。
3. switch 裡如果 case 1: 沒有寫 break，輸入 1 會怎樣？執行完 case 1 的程式之後，會繼續往下執行 case 2（以及更下面的）程式碼，直到遇到 break 或 switch 結束。這叫 fall-through。
4. 可以寫 switch (name) { case "eth0": … } 嗎？不行。case 後面只能是整數常數。比對字串要用 if (strcmp(name, "eth0") == 0)。
5. 為什麼多行巨集要寫成 do { … } while (0)？讓整個巨集在語法上變成一個敘述，而且呼叫時結尾要加分號。這樣放在沒有大括號的 if 底下也能正確運作，後面接 else 也不會出錯。while (0) 代表只執行一次，不是真的迴圈。
6. 輪詢硬體狀態時，為什麼不能寫 while (!(read_status() & READY));？硬體如果壞了、沒插好或沒初始化，READY 永遠不會變成 1，程式就會永遠卡在這裡，整台機器停在開機畫面，而且沒有任何錯誤訊息。要加上次數或時間的上限，逾時就回傳錯誤。
7. 在 C 裡，什麼情況下用 goto 是好寫法？函式中途發生錯誤時，往下跳到函式結尾的清理標籤，依取得的反順序釋放資源（記憶體、檔案、鎖），並從同一個出口回傳。這是 Linux kernel 和 EDK II 常見的寫法。往上跳、拿來代替迴圈則應該避免。
