3. 語言策略：C、C++、Rust 各扮演什麼角色

三種語言都學，但地位不一樣：C 是入場券，C++ 是 BMC 路線的實戰語言，Rust 是幾年後的差異化。時數依這個比重分配，不是平均分。

語言在韌體圈用在哪裡台灣職缺需求（2026 年）在計劃裡的角色時數比重
CUEFI／EDK II、coreboot、U-Boot、Linux kernel 與 driver、MCU 韌體BIOS、BMC、嵌入式職缺幾乎都要求，面試也必考 C 手寫題主線，貫穿全程，任何時候都不能停約 55%
C++OpenBMC 的 userspace（bmcweb、phosphor-*、sdbusplus、entity-manager）、伺服器診斷與測試工具BMC 職缺常寫「C/C++」（緯穎、新唐、Lattice 的 JD 都有）第二語言。階段 2 入門，階段 3 做 OpenBMC 時成為主力約 25%
RustRust for Linux、OCP Caliptra（伺服器的 root of trust）、Microsoft Patina（Rust 寫的 UEFI）、Oxide Hubris、嵌入式（embassy）、uefi crate台灣 ODM 目前很少要求；海外 hyperscaler 和晶片廠的職缺逐漸增加差異化。輕量但不中斷，每個階段都做一個小作品約 20%

四個原則

① 不同時開兩個語言的「入門期」

  • Rust 在階段 1 就開始，跟 C 並行。它的語法跟 C 差很多，不容易混淆；而且 ownership 和 borrow checker 擋下的錯誤，正好就是 C 會默默放過的那些記憶體 bug，兩邊對照著學反而更清楚。
  • C++ 延到階段 2，等 C 的指標和 struct 熟了再學。C++ 外表很像 C，太早混在一起，容易寫成「多了 class 的 C」，而面試要的是純 C。

② 同一個題目用三種語言各寫一次

  • 例如 ring buffer：C 版自己管理記憶體和邊界，C++ 版用 template 加 RAII，Rust 版交給 ownership 保證安全。
  • 這比三種語言各做不相干的練習更能看出差異，也是面試時很好的話題：「同一個問題，三種語言各怎麼處理記憶體安全」。

③ C 永遠是底線

  • 每週至少一半的時間給 C，或給當階段的 C 主題（EDK II、bootloader）。
  • 進度落後時，先暫停 Rust，再縮減 C++（縮到只學 OpenBMC 用得到的範圍），C 不動。

④ 固定的每週節奏

  • 平日 4 晚 × 1.5 小時：當階段的主線（階段 1、2 是 C，階段 3 是 C++ 加 OpenBMC）。
  • 週六 5–6 小時：前半主線，後半第二語言。
  • 週日 1–2 小時：Rust 輕量練習（Rustlings、小作品），或者休息。

10. 實驗環境與預算

不買 x86 build 主機。日常學習在 Mac 上的 ARM64 VM 做，需要真正 x86 環境的時候再開 GCP VM。第一筆硬體支出延到階段 2 的 coreboot 真機。

我的 Mac 是 Apple Silicon（arm64）。VMware Fusion 在 M 系列晶片上只能跑 ARM64 的 guest，不能虛擬化 x86。UTM 雖然能用軟體模擬整台 x86，但大型 build 會慢到不實用。所以分成兩層：x86 的部分交給 QEMU 模擬或交叉編譯，吃效能的部分交給 GCP。

兩層環境

① 日常：Mac 上的 VMware Fusion，裝 ARM64 Ubuntu 24.04

  • Fusion 個人使用免費；想要更輕量可以改用 OrbStack
  • VM 配置建議 4 vCPU、8GB RAM、80GB 磁碟
  • 要裝的套件：build-essential nasm gdb-multiarch qemu-system-x86 qemu-user-static binfmt-support gcc-x86-64-linux-gnu acpica-tools ovmf python3-venv g++ cmake meson ninja-build libgtest-dev。Rust 用官方的 rustup 安裝，不要用 apt 版，之後再加 target：rustup target add x86_64-unknown-uefi thumbv8m.main-none-eabihf
  • 負責：K&R 的 C、OSDev bootloader、EDK II 的交叉編譯（設定 GCC5_X64_PREFIX=x86_64-linux-gnu-，新版 edk2 改叫 GCC_X64_PREFIX）、coreboot（用 make crossgcc-i386）、C++ 和 Rust 的練習、Python Redfish 工具

② x86 的部分：GCP 上的 N2 VM，開啟 nested virtualization

  • 一定要選 Intel 平台的 N2 系列。E2 不支援 nested virtualization，就沒有 /dev/kvm 可以用
  • 建立時加上 --enable-nested-virtualization，裝好後確認 /dev/kvm 存在。這樣 QEMU 就能用 -enable-kvm，跑 OVMF 和 coreboot 幾乎跟真機一樣快
  • 日常實驗用 Spot（--provisioning-model=SPOT），用完就關
  • 負責：CS:APP 的 Bomb Lab、OVMF 和 DXE 的 gdb 除錯（KVM 加速）、OpenBMC 的 Yocto build
  • 建立 VM 的同時就設好帳單預算警示
